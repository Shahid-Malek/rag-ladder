# Hosted L1/L2 operation

**Real VM deployment and public release require the live checks described below.** No real image build, model load, database/tunnel/provider call or VM provisioning was performed during this work.

## Images and dependencies

Compose builds `Dockerfile` targets `app` and `parser`, both Python3.12-slim-bookworm/linux-arm64; cloudflared uses release2026.10.7. App uses60 hashed resolved packages, parser80. `requirements-hosted.in/.txt` and `requirements-parser.in/.txt` are the roots/resolved locks. Full private/L3/evaluation `requirements.txt` stays intact. No Docling/RapidOCR/Qdrant/FlagEmbedding/LangGraph or CUDA packages enter either hosted image. ONNX Runtime belongs to the existing L2 PyMuPDF Layout parser, and stays only in the parser image. The app image retains L3 source to satisfy the existing eager import; hosted L3/admin routes remain disabled and its optional dependencies/models are absent.

The two hashed locks cover hosted L1/L2 only. Optional local L3 imports use the full `requirements.txt`; that dependency list is not a complete hashed lock.

The app build bakes immutable BGE-small/BGE-base/injection-classifier HF snapshots and verifies local loading with socket connections forbidden. The parser build verifies synthetic PDF/OCR with sockets forbidden; PyMuPDF Layout assets come from its pinned wheel and Tesseract English from the OS package. Neither build was executed here. Runtime HF/Transformers are offline; weights/root are read-only. Digest capture, native ABI compatibility and advisory checks still need the real build host.

## Secrets, ingress and storage

Set `RAG_APP_ENV_FILE`, `RAG_TUNNEL_TOKEN_FILE` and `RAG_RUNTIME_DIR` to absolute external paths before a later authorized Compose invocation. Use `docker compose --env-file /dev/null ...` to prevent automatic project `.env` loading. App environment must contain app/Neon/Turnstile/provider configuration only, never the tunnel token. The token is a separate file-backed secret readable only by the owner and tunnel UID65532 as needed. Do not print resolved Compose configuration: it contains app secret values. The image disables dotenv; SlowAPI uses explicit empty `limiter.conf` instead of its implicit working-directory `.env` lookup.

No ports are published. The private internal ingress subnet172.30.0.0/29 has tunnel172.30.0.2 and app172.30.0.3; only the tunnel IP is trusted for CF headers. App/tunnel have separate outbound bridges; parser has `network_mode:none`. Configure the managed tunnel origin `http://app:8000`, expected public Host/HTTPS, and fallback404. Check subnet conflicts and deny all inbound IPv4/IPv6 at Oracle and host layers. Root administrators can still reach bridge IPs.

Owner-run on the VM: `sudo ./provision_runtime_dir.sh /var/lib/rag-runtime.img /srv/rag-runtime`. It creates a dedicated1GiB ext4 loop filesystem, mounts nodev/nosuid/noexec, sets UID/GID10001/mode0700, and refuses unknown existing images/symlinks/nonempty unmounted targets. It prints the exact `/etc/fstab` line to add once; verify reboot persistence before starting Compose. It never formats an existing unknown device/file. No host formatting/mounting was run here. `container_start.py` independently rejects an unmounted, oversized or unwritable runtime. Keep it across restart/down-up: capacity.json, watchdog state and session files are durable. Losing those ledgers is an operational NO-GO; do not erase them to bypass a limit/lock.

## Exact parser boundary

The **only** cross-container mount is Docker's `local` volume driver with `type=tmpfs`, `device=tmpfs`, `o=size=1m,mode=0750,uid=10002,gid=10002,nodev,nosuid,noexec`, mounted at `/run/parser-ipc`. Parser UID/GID10002 has RW; app UID10001 has a RO mount and supplementary GID10002. Parser creates socket `parser.sock` as0660; the group can connect but cannot write the directory, and the app's RO mount prevents create/unlink. Unix socket connect through that RO mount must be proven on the real kernel.

The normal service creates only a socket inode. A compromised parser can write other files within that1MiB IPC mount, but app only connects to the hard-coded socket and never reads/executes/configures itself from those files. App sends bounded upload bytes/metadata; parser writes them to its own private `/app/.cache/parser` tmpfs256MiB, with another private32MiB `/tmp`. App code/config/model/runtime paths are never mounted into parser. App never executes or loads config from IPC. Parser root/code/config are image-owned read-only. Worker environment is an explicit secretless allowlist; no app env file, database URL, keys, model cache or Docker socket exists there. All hosted PDF/image validation, conversion, extraction and hidden-span inspection happen in per-job parser children. App validates returned owner/pages/text/flags/size before using them.

Timeout/Unix-client disconnect kills and reaps the parser job group. Crash/OOM/malformed output produces a generic503 `parser_unavailable`, no user strike; EOF/container loss is handled the same way. Supervisor exits70 after job failure and Compose restarts only parser, with a configured3s launch delay. App remains up and can still answer existing documents; uploads fail safely while parser recovers. No automatic upload replay occurs.

## Watchdog, resources and deletion

A separate lightweight parent supervises the single Uvicorn process group. Before native question/upload/background ingest work, start/deadline/session metadata are durably written/fsynced and acknowledged over a private inherited socketpair. It records completion only after work really stops. At deadline+2s grace it persists the triggering session lock, SIGKILLs/reaps the app group and exits for Compose restart. Stale acknowledged starts lock conservatively after any process crash; a failed final state write still leaves durable starts. Corrupt/unwritable state fails closed. Parent shares the app cgroup but has its own interpreter/GIL; actual scheduler/kill latency still needs VM proof.

Compose environment configures persisted restart backoff10,20,40,...,300seconds; healthy ten-minute operation resets it. The parent waits before spawning the app, so standalone Compose behavior does not depend on Swarm-only delay semantics. Every app restart reloads three models and interrupts all in-flight requests; the killed request may receive a tunnel gateway error. Startup first applies targeted metadata locks before readiness. Kill recovery fetches at most five indexed live-session/pending-job rows (hard cap four), reconciles metadata/local files, and does **no** vector counts, vector DDL/rebuilds, pg_database_size or catalog table enumeration. Due cleanup runs later; orphan retention is scheduled after ten minutes. Startup itself has a300s watchdog deadline. Healthchecks alone do not cause restart.

Caps: app1.5CPU/6GiB/192PIDs, parser0.25CPU/2GiB/64PIDs, tunnel0.25CPU/256MiB/32PIDs; no swap allowance beyond each RAM cap. Temp/shared-memory mounts are explicitly bounded. One app worker, one parser/ingest job, two questions. Runtime admission512MiB sits inside physical1GiB. These are configured ceilings, not measured ARM capacity. JSON logs rotate1MiB x3/service; app metadata traces1MiB/day for30days; terminal summaries/provider counters retain30days. No prompts/documents belong in logs.

Deletion commits token/history revocation and a terminal tombstone first, then deletes owned vectors/index state, jobs, BM25 and files under work locks; success marks data_deleted_at. Failures retain retryable tombstones. End/TTL/restart/orphan paths are idempotent. Startup removes abandoned local staging/uploads; vector FKs prevent ownerless shared rows, and terminal pending cleanup handles owned leftovers. Empty installations do not poll Neon; active-session orphan maintenance is ten-minute and terminal retention is due-only. Provider records/Neon backups are outside live-data deletion guarantees.

## Neon and verification

Run `neon_setup.sql` as owner in a **fresh dedicated PG17+ database**. It is transactional/idempotent, creates owner-owned rag tables/extension and initially NOLOGIN rag_app, revokes CREATE/TEMP and grants required DML only. Enable the role's login/password privately afterward. No legacy per-table migration is attempted. Hosted pool forces rag_app, TLS verify-full, system CA bundle, rag/public search path and statement/lock/transaction limits. Startup checks live TLS, non-owner/non-BYPASSRLS/no-membership identity, no schema/database create rights and forced RLS tables. No runtime schema DDL/TRUNCATE occurs.

Authenticated session scope must match the hashed collection before DB work. Each vector transaction sets local app.session_id; explicit session WHERE precedes exact cosine sorting/top20. Forced RLS also applies to index state. Metadata is a shared service control plane with authenticated-id predicates, not RLS isolation from a compromised app role/process. BM25 remains session-local; RRF60/stable ties/final5 are unchanged. Live pgvector/RLS/pooling behavior remains a VM check.

Before deployment or public release, verify ARM image/model/OCR startup and memory peaks; container/socket/network confinement; watchdog kill/restart timing; runtime mount and ledger persistence across reboot; IPv4/IPv6 firewalls and tunnel/challenge configuration; live Neon role/TLS/RLS/pool reset/deletion; account storage/compute limits and retention. Inspect image configuration/history and every layer for private files and credentials, including files deleted by later layers. These live checks and actual image scans remain unrun.
